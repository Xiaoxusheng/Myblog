# MyBlog 架构设计

## 目录结构

```
D:\myblog
├── server/        Go 后端（:8080）：/api/v1/*  /uploads/*  /rss
├── web/           前台（dev :5173）
├── admin/         管理端（dev :5174）
├── docs/          文档；docs/contracts/ 为唯一契约来源
├── docs/agent/    多 Agent 协作：任务板 + 各角色 status
└── .agent/        任务状态（TASK_STATE / DECISIONS）
```

## 后端分层（server/）

```
main.go        启动、路由装配、静态目录、seed
config/        环境变量配置（全部有默认值，零配置可跑）
common/        统一响应、错误码、分页参数解析
model/         GORM 模型 + AutoMigrate + Seed 数据
middleware/    CORS、JWT 鉴权、评论/登录限流、安全响应头
handler/       public_*.go 与 admin_*.go；博客规模简单业务直接 GORM，不引入 service 层
router/        路由注册
uploads/       上传文件目录（静态服务 /uploads），仅放 .gitkeep 入库
```

- DB 默认 SQLite（`server/blog.db`），驱动 `github.com/glebarez/sqlite`（纯 Go，免 CGO，Windows 友好）
- `BLOG_DB_TYPE=mysql` 时使用 `BLOG_MYSQL_DSN`
- 环境变量：`BLOG_PORT`(默认8080)、`BLOG_JWT_SECRET`(未设置则自动生成落盘 blog.jwt.secret)、
  `BLOG_DB_TYPE`(sqlite/mysql)、`BLOG_DB_PATH`(blog.db)、`BLOG_MYSQL_DSN`、
  `BLOG_SCHEDULE_INTERVAL_SECONDS`(定时发布扫描间隔，默认30s，最小5s)
- 安全：`BLOG_CRYPTO_KEY`（敏感字段 AES-256-GCM 静态加密密钥，未设置则自动生成落盘，
  见 model/crypto.go）、`BLOG_TRUSTED_PROXIES`（可信代理，默认回环+内网段）、
  `BLOG_CORS_ORIGINS`（Origin 白名单，留空放开全部）；登录同 IP 失败 5 次锁定 15 分钟

## 内容生命周期（CMS）

- **版本历史**：`post_revisions` 表按文章存全量快照（v1=首次保存）；仅快照字段真正变化才生成，
  `auto` 自动保存距最新版本 <120s 防抖；恢复 = 先「恢复前快照」再「恢复自 vN」，可撤销，
  不改发布状态；删除文章级联删版本（见 model/revision.go、handler/admin_revision.go）
- **定时发布**：文章 status=3 + `publish_at`；main.go 调度器启动先补跑一次再按
  `BLOG_SCHEDULE_INTERVAL_SECONDS` 轮询，到点 UPDATE 为已发布且 `published_at=计划时间`
  （见 model/schedule.go）；计划存库，重启不丢

## 前端约定

- `web/` 与 `admin/` 均为 Vite + Vue3 + TS；`src/{api,router,stores,views,components,styles,types}`
- dev 代理 `/api`、`/uploads`、`/rss` → `http://localhost:8080`
- API 客户端统一封装（拦截器处理 code!==0 与 401）
- 前台端口 5173，管理端端口 5174

## 启动方式

```
server:  cd server && go mod tidy && go run .      # :8080
web:     cd web && npm i && npm run dev            # :5173
admin:   cd admin && npm i && npm run dev          # :5174  初始账号 admin/admin123
```

## 开发流程（多 Agent 并行）

Contract（docs/contracts）→ 并行开发（Backend / Web / Admin 互不等待）→ Orchestrator 联调 → QA 验收。
前端不等后端：按契约封装 API 层即可开发；联调由 Orchestrator 完成。
