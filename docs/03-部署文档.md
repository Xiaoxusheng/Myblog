# MyBlog 部署文档（Docker Compose）

MyBlog 采用 Docker 部署，共三个服务：

| 服务 | 镜像 | 说明 |
|---|---|---|
| `server` | `./server` 构建（Go 多阶段，CGO_ENABLED=0） | 博客后端 API，监听 8080 |
| `nginx` | `deploy/Dockerfile` 构建（node 构建 web/admin dist + nginx:alpine） | 门户：80=前台、8081=管理端，反代 `/api` `/uploads` `/rss` |
| `mysql` | `mysql:8.0`（utf8mb4） | 数据库，**仅在「全套模式」下启动**（profile: bundled） |

## 前置要求

- Docker Engine 20.10+ 与 Docker Compose v2（`docker compose version` 可用）；
- 服务器可访问 Docker Hub 与镜像源（compose 已内置 goproxy.cn / npmmirror 加速构建期依赖）；
- 端口未被占用：**80**（前台）、**8081**（管理端）、**8080**（API，如不需要直连可与 nginx 一样只走反代）；
- 如复用服务器已有 MySQL，需具备该库的建库权限与账号密码。

## 第 0 步：准备环境变量

```bash
cd /path/to/myblog
cp .env.example .env
vim .env
```

`.env` 中必须修改（**不要使用模板默认值上线**）：

```ini
MYSQL_ROOT_PASSWORD=<强密码>
BLOG_JWT_SECRET=<随机长字符串，如 openssl rand -hex 32 的输出>
BLOG_MYSQL_DSN=root:<与 MYSQL_ROOT_PASSWORD 相同的强密码>@tcp(mysql:3306)/myblog?charset=utf8mb4&parseTime=True&loc=Local
```

> 模式 A 用上面默认的 DSN 即可（把密码两处改一致）；模式 B 的 DSN 写法见下文。

首次构建与启动：

```bash
docker compose build
```

---

## 模式 A：Compose 全套（自带 MySQL，推荐全新服务器）

```bash
docker compose --profile bundled up -d
```

包含：mysql + server + nginx 三个服务。首次启动 MySQL 需要初始化（约 30 秒），server 通过
healthcheck 等 MySQL 就绪后自动建表（GORM AutoMigrate）并写入种子数据。

验证：

```bash
curl http://<服务器IP>/api/v1/site          # 返回 {"code":0,...}
curl http://<服务器IP>/rss                  # 返回 RSS XML
```

## 模式 B：复用服务器已有 MySQL（不启动内置 mysql）

MySQL 服务在 compose 中声明了 `profiles: ["bundled"]`，默认 `up` 不会启动它；
`server` 对 mysql 的依赖为 `required: false`，因此可以只起 `server + nginx`。

1. 在已有 MySQL 中建库（utf8mb4）：

```sql
CREATE DATABASE IF NOT EXISTS myblog DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
```

2. 覆盖后端 DSN（在 `.env` 中追加，账号换成有 myblog 库权限的用户）：

```ini
BLOG_MYSQL_DSN=<用户>:<密码>@tcp(<MySQL主机>:3306)/myblog?charset=utf8mb4&parseTime=True&loc=Local
```

> DSN 必须带 `charset=utf8mb4&parseTime=True&loc=Local`（缺漏时后端会自动补齐并打印警告，
> 但建议显式写全）。MySQL 主机为本机时，容器内不能用 `localhost`，请用 `host.docker.internal`
> （需在 compose 中为 server 追加 `extra_hosts: ["host.docker.internal:host-gateway"]`）
> 或宿主内网 IP。

3. 启动：

```bash
docker compose up -d server nginx
```

其余验证方式与模式 A 相同。

## 访问地址

| 入口 | 地址 | 说明 |
|---|---|---|
| 前台 | `http://<服务器IP>/` | 博客门户（web dist） |
| 管理端 | `http://<服务器IP>:8081/` | 管理后台（admin dist） |
| API | `http://<服务器IP>:8080/api/v1/...` 或经 80 端口 `/api/v1/...` | 后端接口 |
| RSS | `http://<服务器IP>/rss` | RSS 2.0 订阅 |
| 上传文件 | `http://<服务器IP>/uploads/...` | 静态资源 |

**首次登录**：管理端使用初始账号 `admin / admin123`，登录后请立即在「个人资料 → 修改密码」修改，
并确认 `.env` 中 `BLOG_JWT_SECRET` 已改为随机值。

## 数据持久化与备份

| 数据 | 位置 | 卷 |
|---|---|---|
| MySQL 数据 | 容器 `/var/lib/mysql` | named volume `myblog_mysql-data` |
| 上传图片 | 容器 `/app/uploads` | named volume `myblog_upload-data` |

备份：

```bash
# 数据库
docker compose --profile bundled exec mysql sh -c \
  'mysqldump -uroot -p"$MYSQL_ROOT_PASSWORD" --databases myblog' > backup-$(date +%F).sql

# 上传文件
docker run --rm -v myblog_upload-data:/data -v $PWD:/backup alpine \
  tar czf /backup/uploads-$(date +%F).tar.gz -C /data .
```

恢复数据库：`docker compose -i -T ... < backup.sql`（或进入 mysql 容器 source）。

## 常用运维命令

```bash
docker compose ps                        # 查看状态
docker compose logs -f server            # 跟随后端日志
docker compose logs -f nginx
docker compose restart server            # 重启后端
docker compose down                      # 停止（保留数据卷）
docker compose down -v                   # 停止并删除数据卷（危险：数据全丢）

# 更新代码后重建
git pull
docker compose build                     # 或 docker compose --profile bundled build
docker compose up -d                     # 模式 B；模式 A 加 --profile bundled
```

## 常见问题

- **server 反复重启**：`docker compose logs server` 看连接错误。多为 DSN 错误或 MySQL 未就绪
  （healthcheck 会兜底等待；复用外部 MySQL 时检查账号、白名单与 `host.docker.internal`）。
- **上传图片 413**：nginx `client_max_body_size` 已设 20m，如自行调整代理层请同步放宽。
- **时区**：server 容器固定 Asia/Shanghai；MySQL 容器 TZ 同样为 Asia/Shanghai。
- **模式 B 提示 "no such service: mysql"**：属正常——mysql 只在 `--profile bundled` 下存在。
- **Compose 版本**：`depends_on.required: false` 需要 Docker Compose v2.20+（2023 年后版本均满足）。
