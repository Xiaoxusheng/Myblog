# 管理端 UI 设计规范——企业级打磨(Enterprise Polish)

> 版本:v1.0 · 对应改版轮次 M1–M7 · 日期:2026-09-20
> 前置:2026-09-19 管理端已完成一轮「Linear/Vercel 式克制风」升级(--admin-* token、分组侧栏、PageHeader/StatCard/FormSection);本轮不推倒重来,在其基础上做**企业级打磨**。

---

## 0. 一句话定位

上轮立住了骨架(克制风、分组侧栏、基础件),但距成熟企业后台还差四层:**两处功能 bug**(SEO 清单不渲染、系统状态页刷新按钮不渲染)、**三态不统一**(12+ 个列表页把「加载失败」伪装成「没有数据」)、**表格交互未收敛**(评论页 6 个平铺行操作、文章页无批量)、**两套 token 并行未打通**(AntD theme 只有 borderRadius:6,ECharts 全字面量,无暗色)。本轮目标:让管理端达到 AntD Pro / Linear 级的「确定性」——每个状态有交代、每个操作有反馈、每个页面同一套语言。

## 1. 调研依据(GitHub 主流管理端设计交互逻辑)

| 来源 | 关键特征 | 本轮吸收 |
|---|---|---|
| Linear(公认 admin 交互标杆) | 命令面板驱动、紧凑表格 + 键盘优先、行操作收敛、克制动效(150-300ms) | **M3:行操作「查看/编辑/更多」收敛**(评论页 6 个平铺链接按钮是反例);键盘可达性补齐 |
| Stripe Dashboard | single-metric focus、数据表工艺(密度/对齐/tabular-nums)、错误态必带恢复动作 | **M2:三态统一**——错误态必须「发生了什么 + 能做什么 + 重试」;首屏骨架、请求 spinner、按钮 loading 三级 loading 策略 |
| Ant Design Pro(v5/v6 官方模式) | CRUD 同构:`List → Toolbar → Table → Pagination`,批量走 rowSelection + 选中条,操作后 `message → refresh` | **M3:文章列表批量操作**(发布/下架/删除 + 选中条,评论页已有同款对齐);**M2:useTable 抽象**收敛 10+ 页复制样板 |
| AntD 4 官方主题体系 | ConfigProvider token 单一来源;暗色走 `theme.darkAlgorithm`,禁止手写 `.dark` 覆盖堆;静态 message/Modal 不消费主题 → 用 `<a-app>` 上下文 | **M1:Token 打通**(colorPrimary/圆角/控件高度与 --admin-* 同源);**M6:暗色模式** + message/Modal 迁移 useApp |
| rauno.me craft / shadcn admin 模板 | 细节一致性:同族元素同语言、焦点可见、危险操作三级形态统一 | **M7:可访问性与登录页**(行内错误 Alert、键盘路径);删除确认三形态按规范归位(行内 popconfirm / 批量 Modal) |

**共同结论**:成熟 admin 的差距不在「再加东西」,而在「确定性与一致性」——状态有交代、操作有反馈、同族同语言。全部为前端工作,零 API 变更。

## 2. 改 vs 不改

**改**:App.vue(ConfigProvider token 扩展 + a-app 包裹)、styles/main.css(--admin-* 补 dark 分支)、新增 composables/useTable.ts(样板收敛)、components/(错误态组件、批量操作条,若无则新建)、PostListView/CommentView 等 10+ 列表页(接入 useTable、行操作收敛、错误态)、PostEditView(bug 修复)、HealthView(bug 修复)、PageEditView(CMS 化)、SettingsView(FormSection 化)、TrendChart/PvTrendChart(token 化)、LoginView、AdminLayout(键盘可达)、theme 组合式(theme.ts)。

**不改(红线)**:框架栈(Vue3 + Vite + ant-design-vue 4)、路由与页面清单、API 与业务逻辑、登录鉴权流程、上轮已定的布局结构(分组侧栏五组/顶栏三件套)、--admin-* 现有浅色值(只增 dark 分支不改浅色)、ECharts 图表类型与数据。**不引入 Pro Components**(规模不需要,不为了用而用)、**不引入第二套 UI 框架**。

## 4. M1:缺陷修复 + Token 地基

### 4.1 缺陷核查结论(改版前置核查)

1. **PostEditView `seoChecks`:盘点误报,无缺陷**——该计算属性在 script 内已有完整定义(7 项检查),模板渲染正常;Explore 盘点 grep 漏检。M1 实施时以 vue-tsc 构建确认。
2. **HealthView.vue:42 `<template #extra>` 确认缺陷**——PageHeader 只定义 `#actions`,刷新按钮确实不渲染。已修复:改用 `#actions`(PageHeader 不扩插槽,保持单一契约)。

### 4.2 AntD theme token 与 --admin-* 同源打通

- 新建 `admin/src/theme/tokens.ts`:导出 `adminTokens`(颜色/圆角/间距单表,--admin-* 与 AntD token 共同取值);App.vue ConfigProvider 扩展:
  ```ts
  token: {
    borderRadius: 6,
    colorPrimary: '#1677ff',
    colorBgLayout: '#f5f6f8',
    colorBgContainer: '#ffffff',
    colorBorder: '#e6e8eb',
    colorText: 'rgba(15, 18, 25, 0.88)',
    fontSize: 14,
    controlHeight: 32
  }
  ```
- 语义:AntD token 是控件层唯一真相;--admin-* 是布局层(背景/边框/文字灰阶)唯一真相;两者由 tokens.ts 单表派生,不再各写一套。
- ECharts token 化:TrendChart/PvTrendChart 的字面量(#1f6feb 等)改读 tokens.ts 导出色板;两组件 80% 重复逻辑合并为单一基础组件 + props 差异(消双胞胎,符合单一真相来源)。

### 4.3 message/Modal 上下文地基(为 M5 暗色铺路)

- App.vue 以 `<a-app>` 包裹 router-view;新增 `composables/useFeedback.ts`(薄封装:useApp() 的 message/modal + 统一成功/失败文案模式)。
- 本版仅落基础设施,**不**全量迁移静态调用(M5 暗色时随页面触点逐个替换,避免一次性 40+ 处机械 diff 淹没审查)。

## 5. M2:三态统一 + useTable 样板收敛

### 5.1 useTable composable(收敛 10+ 页样板)

- 新建 `composables/useTable.ts`:封装 loading/error/列表数据/分页(current/pageSize/total)/`删除后当前页删空回退一页`/reload;错误时置 error 状态供页面渲染错误态。
- 接入:PostList/PageList/Category/Tag/Series/Link/Redirect/AuditLog/Blacklist/Backup 等表格页;**不改变**各页筛选参数拼装与业务动作(仅替换状态机与样板)。
- MediaView 保持自有网格逻辑,仅对齐三态,不强行套表格抽象。

### 5.2 三态统一策略(全站一个模式)

- **Loading**:首屏(无数据)用 a-skeleton(表格页用 3 行行级骨架形态);翻页/筛选等已有数据请求用 a-table 内置 spinner;提交按钮一律 `:loading`。删掉「表格 spinner 当首屏 loading」的混用。
- **Empty**:表格页统一 `#emptyText` 业务文案(暂无文章/暂无评论/暂无文件…);筛选无结果与真空态文案区分(「没有匹配"xx"的结果,试试调整筛选」)。
- **Error**:请求失败页面渲染页级错误块(a-result status="error" 或统一紧凑错误条:发生了什么 + 建议动作 + 重试按钮),**禁止落回空表伪装无数据**;错误文案规范「加载文章失败,请检查网络后重试」级具体度。

### 5.3 消息与确认归位(核对性)

- 行内删除 a-popconfirm、批量/不可逆 Modal.confirm、登出 Modal——现状已基本正确,仅核对归一;文案保持现有「删除后不可恢复…」风格。

## 6. M3:表格交互升级

### 6.1 行操作收敛(>3 即折叠)

- 规范:行操作 ≤3 个平铺(链接按钮);>3 收敛为「主操作平铺 + `⋯` Dropdown(其余 + 危险项置底红色 + 分隔线)」。
- 落点:评论页(现 6 个:通过/拒绝/垃圾/删除/回复/查看 → 平铺「回复/查看」+ 更多收 4 个);文章页(编辑/分析/查看/删除 → 平铺「编辑/分析」+ 更多收查看/删除);其余页面逐一核对(≤3 保持)。

### 6.2 文章列表批量操作(对齐评论页已有模式)

- PostList 加 rowSelection:选中 → 底部批量条(已选 N 篇):发布/下架(按状态可用性启用)/删除(Modal.confirm);操作成功清空选择 + message + 刷新。
- 复用评论页批量条视觉语言(浅灰条 + 动作 + 取消选择),抽 `components/BatchBar.vue` 共用(评论页同步迁移)。

### 6.3 排序与密度(核对性)

- 数据表时间列开 `sorter`(文章:发布时间;评论:时间;审计:时间;备份:时间)——服务端排序仅在前端已有字段可用时接,不做后端改动:按现有分页接口,时间列排序由后端默认序保证,前端仅做受控 sorter 的页面级实现,**不加后端参数**(红线:零 API);如接口不支持, sorter 仅对本页数据排序并在列头 tooltip 说明「本页排序」。
- 密度:统一 size="middle"(现多数已是),不动。

## 7. M4:编辑器与表单统一

### 7.1 PageEditView 升级(消双标)

- 对齐 PostEditView 的 CMS 形态:顶部工具条(返回 + 大标题输入 + 保存)、≥1200px 左 1fr/右 320px FormSection 分栏、3s 防抖本地草稿 + 未发布静默服务器自动保存、进入恢复询问、32px 底部状态栏(字数/保存状态)。
- 复用 PostEdit 的自动保存逻辑:抽 `composables/useAutoSave.ts`(PostEdit 同步迁移,消重复;diff 恢复询问语义不变)。

### 7.2 SettingsView FormSection 化

- 单长卡水平表单 → vertical 表单 + FormSection 分组(站点信息/SEO/评论/交互功能),与 PostEdit 右栏同语言;水平 label-col 模式仅保留在超长配置项(如需要)。
- 各 Modal 表单维持 vertical;slug 正则等重复校验收敛到 `utils/validators.ts`(Category/Tag/PostEdit 三处同源)。

## 8. M5:暗色模式

### 8.1 机制(禁止手写 .dark 覆盖堆)

- `theme.ts`:lightTokens/darkTokens 两表;App.vue 按 store 切 `theme.algorithm`(defaultAlgorithm/darkAlgorithm)+ token 覆盖;--admin-* 增加 `html.dark` 分支(布局层背景/边框/文字灰阶,背景避免纯黑:bg #141414 系)。
- 侧栏现有深色 #001529 在暗色下改为与整体一致的面板色(线性层次:布局 bg → 侧栏/卡片 surface → 浮层)。
- ECharts:色板从 tokens.ts 取,暗色轴/分割线/文字色随主题切换(组件 watch 主题重设 option)。

### 8.2 触点跟随

- 静态 message/Modal.confirm → useFeedback(useApp 实例),随 M2/M3/M4 触碰的页面顺带迁移,本版扫尾核对;toast 浮层在暗色下正确。
- AdminLayout 顶栏/面包屑/通知 Popover、Drawer/Modal/Popconfirm 由 darkAlgorithm 自动接管,逐页目视核验。
- 主题切换入口:顶栏用户区相邻加 icon-btn(太阳/月亮),偏好存 localStorage + 跟随系统默认。

## 9. M6:登录页与可访问性

### 9.1 登录页

- 保持居中卡形态与克制风:加站点品牌区(站名衬线/字距 logo 行,与管理端零装饰语言一致)、错误改**行内 a-alert**(全局 toast 保留兜底)、按钮 large + loading、7 天免登录开关不动;不加插画/渐变(红线:企业后台禁装饰堆砌)。

### 9.2 可访问性(盘点缺口逐项)

- AdminLayout 用户下拉触发器补 keydown.enter/space;通知项改可聚焦(button 或 role=button+tabindex+keydown);评论表格行加键盘路径(行内「查看」已有链接语义即可,整行 click 保留鼠标便利)。

- index.html 补 favicon(admin 侧简单标记即可,不引字体资源)。
